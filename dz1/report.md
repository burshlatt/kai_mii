# Сравнительный анализ AI-агентов для «Дедлайна»

## 1. Задача и требования

Задача: учебный трекер заданий. Студент регистрируется, ведёт свой список (предмет, дедлайн, статус, приоритет), видит просрочку и фильтрует список. Позже к этому добавляются PostgreSQL, тесты, OAuth и CI.

Требования, из которых выбирался инструмент:

- Сложность средняя: не лендинг, а приложение с сессией, базой и тестами.
- Нужен доступ к локальным файлам, терминалу и уже запущенному PostgreSQL.
- В репозитории будут пароли только в `.env`, который не коммитится. Код и учебные данные не должны жить исключительно в чужом облаке.
- Бюджет студенческий. Инструмент уже открыт в этой среде — Cursor. Платить за второй облачный конструктор ради той же работы не требуется.

Требование зафиксировано до таблицы: инструмент должен править существующий репозиторий и запускать проверки, а не только нарисовать первый экран.

## 2. Сравнительная таблица

Шкала 1–5. Больше — лучше именно для этой задачи, а не «вообще». Оценки на октябрь 2026 года, по публичному поведению продуктов.

| Критерий | Bolt.new | Lovable | Cursor | GitHub Copilot |
| --- | --- | --- | --- | --- |
| Тип | Cloud | Cloud | IDE-агент | IDE-агент |
| Доступ к контексту проекта | 2 | 2 | 5 | 4 |
| Скорость генерации | 5 | 5 | 4 | 4 |
| Качество кода для этого стека | 3 | 3 | 4 | 4 |
| Стоимость | 3 | 3 | 4 | 3 |
| Безопасность данных | 2 | 2 | 4 | 4 |
| Интеграция в процесс | 2 | 3 | 5 | 4 |
| Сумма | 17 | 20 | 26 | 23 |

Почему так:

- **Контекст.** Bolt и Lovable работают в браузере со своим проектом. Локальный каталог, пользовательский кластер PostgreSQL и файл `.cursorrules` они не видят. Cursor читает репозиторий, терминал и правила. Copilot хорошо видит открытые файлы и репозиторий в редакторе, но проектные правила и многошаговый прогон с отдельными субагентами здесь слабее.
- **Скорость.** Облачные конструкторы быстрее выдают первый экран: промпт сразу становится приложением в их хостинге. Cursor и Copilot медленнее на старте, потому что правят файлы и ждут установки зависимостей.
- **Качество.** Для прототипа интерфейса облачные агенты достаточны. Для SQL с владельцем строки, CSRF и тестов нужен агент, который остаётся в репозитории и может прогнать `npm test`. Здесь IDE-агенты ровнее.
- **Стоимость.** У Bolt и Lovable удобный бесплатный порог кончается на частных проектах и генерациях. Copilot — отдельная подписка. Cursor уже используется для этой работы.
- **Безопасность.** В облачном агенте схема базы и будущие учебные записи проходят через их сервис. IDE-агент тоже отправляет фрагменты кода в модель, но репозиторий, `.env` и база остаются на машине. Для студенческого списка заданий этого достаточно. Для персональных данных большого числа людей ни один из четырёх вариантов сам по себе не заменяет политику хранения.
- **Процесс.** Нужны коммиты в свой GitHub, локальный запуск и отчёты рядом с кодом. Lovable умеет отдавать проект в GitHub, но цикл «правка — тест — лог API» остаётся снаружи. Cursor закрывает этот цикл в одном окне.

В обзор ещё попали Replit Agent (облако со своей VM, удобный хостинг, те же вопросы про данные) и Cline (локальный агент со своим ключом API). В таблицу они не вошли: для сдачи хватает двух облачных и двух IDE-инструментов, а выбор между Cline и Cursor упёрся бы в то, что правила и субагенты этого задания уже завязаны на Cursor.

## 3. Выбор

Выбран **Cursor**.

Решающие факторы:

1. Задача живёт в локальном репозитории, а не в одноразовом превью.
2. Файл `.cursorrules` — отдельный артефакт задания 2, и его читает именно этот агент.
3. Нужны терминал, тесты и PostgreSQL на своей машине.
4. Проверка промптов делалась запуском субагентов в том же окружении. Их ответы легли в отчёт как есть.

**Почему не Bolt.new и не Lovable.** Они выигрывают, если цель — за вечер показать кликабельный экран без базы. Здесь следом идут миграции, RLS-подобная проверка владельца, CSRF и CI. Переносить это из их проекта в свой репозиторий — вторая работа. Плюс учебные записи оказались бы в чужом контуре раньше, чем появился свой `.env`.

**Почему не GitHub Copilot как основной.** Он близкий запасной вариант: те же локальные файлы и нормальная цена для студента, если подписка уже есть. Для этого курса слабее связка «файл правил + отдельные прогоны с правилами и без + цепочка промптов». Copilot остаётся уместным для точечных правок внутри уже настроенного репозитория.

## 4. Настройка

Cursor уже был средой выполнения. Дополнительно для проекта:

- в `deadline/.cursorrules` положены те же правила, что в `dz2/rules.md`;
- Node.js 22 установлен локально в домашний каталог, потому что в системе его не было;
- PostgreSQL 16 поднят отдельным кластером на `127.0.0.1:5433` от имени пользователя `deadline`, без правки системной роли;
- MCP не подключался: базе не нужен внешний сервер контекста, SQL лежит в репозитории.

Облачную регистрацию в Bolt или Lovable не делал. Для выбранного инструмента она не нужна, а заводить аккаунт ради скриншота чужого продукта не входит в настройку рабочего окружения.

## 5. Практический прогон

Маленькая задача выбранному агенту: две чистые функции, `isOverdue` и `formatDueLabel`. Промпт требовал явные `export function`, запрет `any` и default-экспорта, локаль `ru-RU`, текст «Дата не указана» и приставку «Сегодня» для того же календарного дня.

Субагент: [Функция просрочки](ad05d20a-c73b-46ce-9c05-789955d275d1). Сырой ответ: `dz2/agent_outputs/dz1_practice/response.md`, код: `due.ts`.

Итерация одна. Функции сразу совпали с контрактом: готовое задание не просрочено, битая дата даёт `false` и подпись «Дата не указана», сегодняшний день собирается из частей `Intl`, а не из строки локали с неразрывными пробелами. Проверка запуском:

```text
isOverdue('2026-10-09T00:00:00.000Z', 'todo', '2026-10-10T00:00:00.000Z') === true
isOverdue(..., 'done', ...) === false
formatDueLabel(тот же местный день) === 'Сегодня, 10 окт.'
formatDueLabel('nope', ...) === 'Дата не указана'
```

Сложность прогона: агент не полез в остальные файлы, как и просили. Отдельно пришлось запускать код самому, потому что субагент только записал файл.

## 6. Выводы

Для «Дедлайна» облачный агент уместен как черновик экрана, и в задании 3 так и сделано: три статических концепции. Основной цикл — IDE-агент с правилами, терминалом и тестами.

Рекомендация на следующий проект того же размера: начать в Cursor с короткого `rules.md` до генерации компонентов. Задание 2 показало, что без правил агент подписывает статус «Выполнено» и добавляет default-экспорт, хотя задача этого не просила. Облачный конструктор оставить для дня, когда нужно показать заказчику картинку, а не миграцию.
