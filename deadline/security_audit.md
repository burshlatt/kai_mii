# Отчёт по безопасности

Проверялись зависимости (`npm audit`), заголовки ответа, SQL, сессия, CSRF и то, что попадает в лог. Код после правок перечитан, аудит запущен повторно.

## Найденное и исправленное

### 1. Уязвимые зависимости фронтенда

Первый `npm audit` после установки показал 15 проблем, среди них critical в Vitest (`tinypool`, чтение файлов через UI тестов) и high в цепочке Tailwind 3 (`braces`, отказ в обслуживании на глубокой вложенности). React Router 6 имел moderate: открытый редирект и конструктор при гидратации.

Исправление: Tailwind 4.3.3, Vitest 5.0.3, `react-router-dom` 7.18.4. Повторный `npm audit` на `frontend` и `backend`: `found 0 vulnerabilities`. В CI стоит `--audit-level=high`, сейчас он проходит и на moderate тоже пусто.

### 2. HSTS на локальном HTTP

`curl` к API показал `Strict-Transport-Security: max-age=31536000`. Заголовок ставил helmet. На адресе без TLS браузер может запомнить, что дальше нужен только HTTPS, и перестать открывать локальный сайт.

Исправление: `hsts: false` в приложении. На боевом HTTPS заголовок должен добавить прокси, который терминирует TLS. В nginx для статики добавлен Content-Security-Policy: скрипты только свои и `mc.yandex.ru`, фреймы запрещены, стили шрифтов только с Google Fonts.

### 3. Что закрыто в коде сразу, до отдельного «раунда починки»

Это не оставленные дыры. Их проверяли и оставили в реализации:

- SQL только с параметрами. Имена колонок в `UPDATE` берутся из белого списка, не из тела запроса.
- Чужое задание не читается: в `WHERE` всегда `user_id` сессии. Интеграционный тест ждёт 404.
- Пароль — bcrypt cost 12. В JSON пользователя хеша нет. Неверный вход не сообщает, существует ли почта.
- JWT в httpOnly-cookie, путь `/`, `SameSite=Lax`. Секрет короче 16 символов не даёт стартовать.
- CSRF на POST, PATCH и DELETE. Регистрация и вход cookie ещё не используют как доказательство, их ограничивает лимит попыток и общий текст ошибки.
- OAuth сверяет `state`. Почта, уже занятая паролем, не привязывается молча.
- Логи не содержат тело запроса. Реальный лог входа есть в `backend_documentation.md`: пароля в строке нет.
- Сид демо-пользователя не запускается при `NODE_ENV=production`.
- `.env` в `.gitignore`, в репозитории только `.env.example`.

XSS: интерфейс не использует `dangerouslySetInnerHTML`, тексты заданий выводит React. Отдельной санитизации HTML нет, потому что HTML не вставляется.

## Что остаётся на владельца стенда

- Поставить свой `JWT_SECRET`, не пример из `.env.example`.
- Включить `COOKIE_SECURE=true` только вместе с HTTPS.
- Завести ключи OAuth в кабинете провайдера и не коммитить их.
- Повесить внешнюю проверку на `/api/health`, когда появится публичный адрес. В compose тревога уже есть: сервис `monitor` пишет `health alert`, если проверка не 200 или база не `up`.
- Лимит входа хранится в памяти процесса. Несколько реплик API без общего хранилища лимит не разделят. Для одного контейнера этого хватает.
- Подтверждения почты нет. Для личного учебного списка это принято: кто знает пароль, тот и владелец.

## Рекомендации

Перед публикацией прогнать `npm audit` в обеих папках и не закреплять `npm audit fix --force` вслепую: в этот раз мажорные обновления Vitest, Tailwind и React Router прошли тесты, следующий мажор надо читать отдельно. На HTTPS включить HSTS на прокси, не в приложении, которое ещё открывают по HTTP.
