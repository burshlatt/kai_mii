# Библиотека промпт-шаблонов

Каждый шаблон собран по схеме Role, Task, Context, Format. Пример — это промпт, которым пользовались в этой работе, и короткий итог прогона. Полные сырые ответы лежат в `agent_outputs/`.

## 1. Генерация компонента

**Role:** Ты senior frontend-разработчик проекта «Дедлайн». Пишешь React и TypeScript без UI-китов.

**Task:** Создай компонент `AssignmentCard`. Он показывает название, предмет, дедлайн и статус учебного задания.

**Context:** Пропсы: `title`, `course`, `dueAt` (ISO), `status` (`todo | in_progress | done`), `isLoading`, `error`. Порядок состояний: загрузка, ошибка, пустое название, заполненная карточка. Тексты на русском. Правила проекта — в `rules.md`, если прогон идёт с файлом правил.

**Format:** Сначала план на 2–4 пункта, затем целый файл `AssignmentCard.tsx` без заглушек. У корня класс `assignment-card` и `data-testid` состояния.

**Пример.** Один и тот же текст задачи отправили двум субагентам. [Карточка без правил](cc78448f-b3fe-4462-8dc3-83a4eb4bb2b2) правила не видела. [Карточка с правилами](96d637a9-3c10-473f-a0f2-184d9aba46ab) сначала прочитала `rules.md`. Сравнение — в `testing.md`. С правилами появились фиксированная подпись «Готово», `data-testid` на всех состояниях и исчез default-экспорт.

## 2. Рефакторинг

**Role:** Ты senior-разработчик, который улучшает уже написанный модуль, не меняя внешнее поведение.

**Task:** Разложи расчёт просрочки, сводки и сортировки на маленькие функции. Убери повторное чтение системных часов из чистого кода.

**Context:** Просрочка — это валидная дата строго раньше `now` и статус не `done`. Сводка считается по исходному списку. Входной массив не мутируется. `now` приходит аргументом.

**Format:** План, затем целый модуль. Кратко перечисли, какие краевые случаи закрыты: пустой список, готовое задание в прошлом, битая дата, пробелы в предмете, `onlyOverdue` вместе со статусом `done`.

**Пример.** Этот шаблон стал промптом шага 2 цепочки. Субагент [CoT шаг 2 функции](cbfd3c36-7c0c-4726-b86d-d62ddeac935b) записал `agent_outputs/cot/dashboard.ts`: отдельные функции разбора даты, просрочки, сводки, сравнения и сборки дашборда. Исходный массив не сортируется на месте, порядок при равных ключах держится через индекс.

## 3. Тесты к существующему коду

**Role:** Ты разработчик, который фиксирует спецификацию тестами и не подгоняет ожидание под случайную реализацию.

**Task:** Напиши модульные тесты на `isAssignmentOverdue`, `summarizeAssignments`, `filterAssignments`, `buildDashboardData`.

**Context:** Каждый тест сам задаёт список, фильтр и `now`. Системные часы не читаются. Обязательные случаи: пустой список, все `done` в прошлом, битая дата, пробелы и регистр предмета, `onlyOverdue` вместе с `done`, устойчивый порядок при равных датах, входной массив после вызова тот же.

**Format:** Отдельный тест на каждый случай, говорящие имена. В утверждениях проверяй и состав списка, и все поля сводки. Без браузера.

**Пример.** Промпт ушёл субагенту [CoT шаг 3 тесты](6a2d4d0e-9e77-4712-8620-b2e50fce2a78). Файл тестов — `agent_outputs/cot/dashboard.test.ts`, отчёт запуска — `agent_outputs/cot/step3.md`.

## 4. Исправление ошибки

**Role:** Ты разработчик, который чинит один дефект и не переписывает соседний код.

**Task:** Найди, почему ответ API на локальном HTTP отдаёт `Strict-Transport-Security`, и убери этот заголовок из приложения.

**Context:** Заголовок пришёл от `helmet` на `http://127.0.0.1:3001/api/health`. Для localhost по HTTP он заставляет браузер в следующий раз идти на HTTPS. На боевом HTTPS заголовок должен ставить обратный прокси, не приложение.

**Format:** Назови причину, покажи точечное изменение, не трогай остальные заголовки безопасности.

**Пример.** Причина нашлась в выводе `curl`: `Strict-Transport-Security: max-age=31536000`. В `deadline/backend/src/app.ts` у `helmet` выставлено `hsts: false`. Остальные заголовки helmet сохранены. В nginx для статики добавлен Content-Security-Policy.

## 5. Декомпозиция сложной задачи

**Role:** Ты аналитик предметной области. На этом шаге код писать нельзя.

**Task:** Разложи фильтрацию и сводку заданий дашборда на логические шаги. Зафиксируй типы и краевые случаи. Сформулируй промпты следующих шагов.

**Context:** Список заданий, фильтр (`status`, `course`, `onlyOverdue`) и внешний `now`. Просрочка не включает `done` и битые даты. Сводка считается до фильтра. Сортировка: просроченные, затем дата по возрастанию, затем название локалью `ru`.

**Format:** Нумерованные шаги с объяснением, почему шаг стоит именно здесь. Типы TypeScript без функций. Таблица краевых случаев. Два готовых промпта со структурой Role / Task / Context / Format.

**Пример.** Субагент [CoT шаг 1 спецификация](c39ab708-c503-4ca4-80dd-dcc47e0503df) записал `agent_outputs/cot/step1.md`. В ответе четыре шага: признак просрочки, сводка по полному списку, отбор конъюнкцией, сортировка видимого списка. Промпты шагов 2 и 3 из этого файла ушли следующим субагентам без переписывания условий.
